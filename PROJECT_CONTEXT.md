# Project Context

## Purpose

This bachelor project forms fair teams for an annual church camp. It imports camper responses from CSV, models team assignment as a mixed-integer optimization problem, and produces team assignments for review or export.

The default target is five teams, but the number of teams is configurable. Fairness means balancing team size, camper age groups, gender categories, and self-reported skills while respecting explicit relationship and capacity constraints.

## Runtime and entry points

- Python 3.10 is the documented runtime.
- `main.py` is the primary entry point.
- `python3 main.py` starts the NiceGUI application.
- `python3 main.py --no-gui` runs the optimizer from the command line.
- Gurobi is the default solver and requires a license. CBC can be selected with `--solver CBC`.
- `update_teams.py` is a separate administrative script that upserts generated team IDs into Supabase.

Important CLI options include:

- `--input`: camper CSV; defaults to `data/people/campers_sample.csv`.
- `--group`: number of teams; defaults to `5`.
- `--relations`: optional relationship-constraint CSV.
- `--sizes`: optional semicolon-delimited size-capacity CSV.
- `--solver`: solver name, normally `GRB` or `CBC`.
- `--timeout`: solver timeout in seconds; defaults to `120`.
- `--output`: output directory.
- `--no-output`: skip CSV and PDF generation.
- `--print`: print assignments to the terminal.
- `--verbose`: enable solver output.

## Architecture and data flow

1. `main.py` parses CLI arguments and stores them in `app_config.args` for shared access.
2. `csv_reader.py` reads camper, relationship, and optional size-capacity CSV files using the column names in `csv_schema.py`.
3. `person.py` converts each camper row into a `Person` with normalized enums, age group, answers, and eventual team assignment.
4. `formation.py` builds and solves the mixed-integer model.
5. Successful assignments are written to a timestamped CSV and rendered to PDF by `pdf_export.py`, unless output is disabled.
6. The NiceGUI screens under `gui/` provide upload, constraint editing, optimizer execution, statistics, and results views.
7. `update_teams.py` can read the generated CSV and upsert `id`/`team_id` values into the Supabase `users` table.

## Optimization model

`formation.form_teams` creates a binary assignment variable for every camper/team pair. Every camper must be assigned to exactly one team.

The objective minimizes imbalance across teams for:

- leadership
- creativity
- Bible knowledge
- physical fitness
- musical ability
- prior camp experience
- acting/performance experience
- costume and prop design
- men, women, youth, kids, and babies age/gender categories

Team size is treated as a soft constraint around the average size with an allowed deviation of two. The model also supports:

- `TOGETHER` relations, which force two campers onto the same team.
- `SEPARATE` relations, which prevent two campers from sharing a team.
- Per-team limits for camper size labels when a sizes CSV is provided.

Small random objective weights are applied to help vary otherwise equivalent solutions. A result is currently accepted only when the solver reports `OPTIMAL`; timeout or other feasible-but-not-proven-optimal states return no solution.

## Main files

- `main.py`: CLI parsing, GUI/CLI selection, orchestration, and PDF export.
- `formation.py`: optimization variables, constraints, objective, solving, and CSV output.
- `person.py`: `Person`, answer, gender, age-group, and relation domain types.
- `csv_reader.py`: pandas-based input parsing for campers, relations, and size capacities.
- `csv_schema.py`: exact external CSV column-name mappings.
- `relations.py`: older relation CSV reader using files under `data/relations/`.
- `pdf_export.py`: formatted PDF reports and team statistics.
- `gui/`: NiceGUI layout, settings, optimizer dashboard, and results pages.
- `update_teams.py`: optional Supabase synchronization utility.
- `data/`: sample camper and relation inputs.
- `output/`: generated CSV/PDF artifacts.
- `solutions/`: saved solver solution files.

## Input and output contracts

Camper CSV headers are defined centrally in `csv_schema.py`; do not silently rename them in only one place. The optional `Size` column is supported. Answers to the first eight questions become numeric enum values used by the optimizer; questions 9 and 10 provide human-entered relationship information.

Relationship CSV rows identify two campers by UUID and use `TOGETHER` or `SEPARATE`. Rows referring to unknown camper UUIDs are skipped by the pandas reader.

The sizes CSV uses `;` as its delimiter. Its first column is `sizeLabel`; remaining columns represent teams and contain capacities.

Successful runs can produce:

- `output/teams_YYYY_MM_DD_HH_MM_SS.csv` with `ID`, name, and team columns.
- A PDF report generated by `pdf_export.py`.
- `solutions/last_saved.sol` when a GUI user saves the current solver model.

## Dependencies and environment

Core dependencies are declared in `requirements.txt`: Python-MIP, Gurobi, pandas, NiceGUI, pywebview, ReportLab, ISO country data, dotenv, and date parsing.

`update_teams.py` imports the Supabase Python client and expects `SUPABASE_URL` and `SUPABASE_KEY` in an env file. Confirm that the Supabase package is installed before using that script; it is not currently listed in `requirements.txt`.

Never commit secrets or real camper data. Treat camper names, birth dates, relationship information, and UUIDs as personal data.

## Development guidance

- Preserve the column-name contract in `csv_schema.py` when changing ingestion.
- Keep GUI and CLI execution paths working; both call the same formation pipeline.
- Be careful with zero campers, invalid dates/answers, unknown UUIDs, solver timeouts, and infeasible capacity/relationship combinations.
- Generated `output/`, solver files, caches, virtual environments, and local env files should remain untracked.
- There is currently no automated test suite or declared lint/type-check configuration. Validate changes with focused tests or small sample runs, and avoid claiming broad regression coverage without adding it.
- The working tree may contain unfinished user changes. Inspect `git status` and preserve unrelated edits.
